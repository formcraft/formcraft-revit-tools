## Findings for the bridge (proposed F-075 to F-078; not filed as issues yet)
- **F-075 `fmc_rhino part` has no file input.** Every cage travels through the chat. One sofa round is about 57 KB of
  JSON, and about 95% of that is face lists the bridge could build itself. Fix: `parts_file` (a path in staging) on `part`.
- **F-076 Every `part` reply repeats the facts for all parts** (about 12 KB per call), not only the parts just built. Fix:
  facts only for `built` plus a one-line total, with `describe` for the full list.
- **F-077 Add parametric cage ops to `RhinoParts.cs`** (this is the real fix for F-075). The reference implementation is in
  `tests/recipes/practice/sofa_midcentury/build_r7.py` (`plate`, `sweep`, `lattice`, `check_cage`). Port them as:
  - `plate`: a bent sheet from section stations (y → z bottom, z top, x offset) plus thickness. Use it for shells,
    bent-ply panels and curved casework sides.
  - `sweep_cage`: a chamfered rectangle swept along a plan polyline, closed with capped ends. Use it for arms, rails and
    rims. This is different from `sweep_path`, which is a hard NURBS sweep.
  - `lattice`: box node lines plus named pulls (seam lines pulled back, field centres pushed forward, crown), with
    doubled seam loops so seams stay crisp. Use it for cushions, mattresses and tufted panels.
  - Validate in the bridge the way `check_cage` does: every edge used once each way, positive volume, and auto-flip.
  This turns "change the side profile" into a one-line edit and a round from ~60 KB into ~3 KB.
- **F-078 `render` always overwrites `<family>_3d_<view>.png`,** so rounds can't sit side by side unless they are staged at once.
  Fix: an optional `label` (for example `r7`) added to the file name.
